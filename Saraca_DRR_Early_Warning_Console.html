Why this exists · two reference events

The gap is data, and then the response

E.01 · Nepal–Tibet floods · 26–30 Aug 2026

A glacier collapse upstream, and no line to the other side

A glacier collapse near Langtang Lirung sent a flash flood down the Bhotekoshi/Lhende Khola valley, striking Rasuwa and Nuwakot in Nepal and Gyirong County in Tibet. USGS seismic analysis later pointed to a glacier collapse and debris avalanche rather than a classic GLOF.

Nepali officials reported they could not reach counterparts on the Chinese side in the immediate aftermath. Across the Koshi, Gandaki and Karnali basins, no formal real-time cross-border data-sharing mechanism exists, although most upstream catchments of the region's glacial lakes lie outside Nepal.

E.02 · Cyclone Ditwah · 26 Nov – 4 Dec 2025

The forecast crossed the border. The response lagged.

IMD tracked Ditwah well, and Sri Lanka's Disaster Management Centre issued Red alerts roughly 72 hours before landfall and coordinated the relocation of more than 61,000 people. The data reached Sri Lanka in time.

Post-event analysis still found the response "less proactive, rather reactive", with delayed action and no single authoritative voice issuing warnings. Ditwah was not a clean success; it shows where the chain breaks once data arrives.

Open, shared, real-time data seems necessary but not sufficient. It has to connect to clear, coordinated response protocols on the ground.

Sources: Wikipedia, "2026 Nepal–Tibet floods"; The Diplomat, 28 Aug 2026; Al Jazeera, 28 Aug 2026; Kulkarni et al., Weather (2026); WHO Sri Lanka; ScienceDirect, "Cyclone Ditwah: What next for Sri Lanka beyond the storm" (Jan 2026).

04 · Monitoring points · rainfall and river discharge forecasts

By country

Rainfall: Open-Meteo Forecast API, daily precipitation sum (mm) in local calendar days; "Yesterday" is a model value, not a gauge observation. IMD categories are defined for 24 hours ending 08:30 IST, so this is an approximation. River discharge: Open-Meteo Flood API (GloFAS), nearest 5 km river cell; the baseline is the median of the previous 31 days. City coordinates are approximate centres.

05 · Early-warning rules

What counts as an alert

Rules marked Official apply a published scale. Rules marked Illustrative have no official regional standard; their numbers are choices for this demo, editable here, and should not be read as operational thresholds. The mapping from categories to the three alert tiers (Watch, High, Severe) is this dashboard's own.

07 · What this build is not

An on-demand demo, not a 24/7 monitor

This page only checks when someone opens it or presses "Check now". If nobody has it open, nothing is checked and no email goes out. True unattended early warning needs a scheduled job that runs outside the browser, calls the same APIs, applies the same rules and sends the alert.

One free route is a GitHub Actions scheduled workflow running a small Node script. Two caveats apply: GitHub may delay scheduled runs at busy times, and it disables schedules in public repositories after 60 days without activity. EmailJS also blocks calls from outside a browser unless you enable non-browser access and use your private key, stored as a repository secret.

on:
  schedule:
    - cron: "0 */3 * * *"   # every 3 hours, UTC
  workflow_dispatch:
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: node check.js     # same APIs + rules as this page
        env:
          EMAILJS_PRIVATE_KEY: ${{ secrets.EMAILJS_PRIVATE_KEY }}
Other limits worth stating
  • These are global models (ECMWF IFS via Open-Meteo; GloFAS). They do not replace Nepal DHM, Bhutan NCHM or Sri Lanka DMC/DoM warnings, which remain the authoritative voice.
  • GDACS may need a public CORS relay. A third-party proxy sees the request and can fail or be rate-limited; it is acceptable for a demo, not for operations.
  • GloFAS discharge at a city point snaps to the nearest river cell. It may reflect a different river than the one that matters locally.
  • No glacial-lake or GLOF feed exists among these five APIs. The E.01 hazard type would not be seen here directly.

09 · Method and sources

How the numbers are made

  • Rainfall. Open-Meteo Forecast API, ECMWF IFS 0.25° where available (falls back to Open-Meteo's default model mix if that model is refused), daily precipitation sum. Model run time from Open-Meteo's model metadata endpoint where it responds.
  • River discharge. Open-Meteo Flood API, derived from Copernicus GloFAS. The API exposes daily values but not a forecast issue time, so the page shows the latest data date and the retrieval time, labelled as such.
  • Earthquakes. USGS FDSN event service (/fdsnws/event/1/query, GeoJSON), last 30 days, M2.5 and above. The PAGER alert level is used when USGS publishes one.
  • Fires, storms, volcanoes. NASA EONET v3 open events, last 60 days.
  • Multi-hazard. GDACS event list API, last 30 days, filtered to Nepal, Bhutan and Sri Lanka by ISO3 code, affected-country list, or location.
